# 原图/增强图双分支接入设计

本页记录下一阶段的最小改动边界，避免把“增强图替换原图”误当成论文中的
双图信息融合。

## 当前数据流

1. `feature_tracker_node.cpp` 从单一 `image_topic` 读取灰度图。
2. `FeatureTracker::readImage()` 产生一套光流轨迹和全局特征 ID。
3. `/feature_tracker/feature` 用 `sensor_msgs/PointCloud` 发布归一化坐标；
   `channels[0]` 只编码特征 ID 和相机 ID。
4. `estimator_node.cpp` 把消息转成
   `map<int, vector<pair<int, Vector3d>>>`；此后 `FeaturePerFrame` 不再保留
   图像来源信息。
5. 当前式（2）—（9）实现按目标帧汇总全部视觉 Jacobian，无法分别得到原图
   和增强图的图像层权重。

## 忠实接入所需改动

1. 增加同步的原图与增强图输入，并各自维护一套光流状态和 ID 命名空间。
2. 只对增强分支调用现有 `BlockNoiseRemover`；原图分支不做 BNR。
3. 在特征消息中增加 `source` 通道（0=raw，1=enhanced），不能借用 camera ID，
   因为相机外参语义不同。
4. 将观测类型扩展为包含 `source`，并在 `FeaturePerId` 或
   `FeaturePerFrame` 中持久保存来源。
5. 构建协方差时按 `(frame, source)` 分组，分别计算原图和增强图的图像层
   权重；约束层权重仍按各自特征轨迹长度计算。
6. 把两套视觉残差同时加入 Ceres，与同一组 IMU 残差联合优化。
7. 日志增加每帧两路特征数、BNR 剔除数、两路 `alpha/beta/hybrid` 权重，
   以便验证论文所述的明暗场景权重切换。

## 验收条件

- 关闭双分支选项时，现有基线轨迹和消息格式不变。
- 开启后每帧能同时观测 raw/enhanced 两类来源，ID 不冲突。
- BNR 始终保证增强分支在原始特征数超过 8 时不少于 8 个约束。
- 单元测试覆盖来源序列化、按来源协方差分组和 BNR 保护。
- 先跑一条 EuRoC 序列检查数值与日志，再固定配置跑全 11 条；代理增强结果
  单列保存，不覆盖基线和双层权重结果。

## 实施状态（2026-09-11）

上述 1—7 项已经实现并编译。`dual_feature_tracker` 同步读取原图和增强图，
发布四通道特征消息；估计器持久保存来源并按来源记录权重；运行脚本在退出节点
后再复制日志，避免缓冲数据丢失。身份图像 30 秒冒烟测试验证两路各 2695 条
权重记录；真实灰度 DCE 15 秒测试触发 BNR，并输出有效短轨迹。

固定参数的 11 条完整代理运行均按判据成功，ATE 与覆盖率逐序列记录在
`results/dual_branch_proxy_summary.csv`。修正轨迹表头识别后的双分支平均 ATE
为 `0.1986423 m`，相对 VINS-Mono 基线均值降低 `9.47%`，相对仅式（2）—（9）
权重均值降低 `5.59%`；两组精度胜率均为 7/11。每条运行的原图/增强图权重行数
完全相等，BNR 只作用于增强分支；负结果（例如 `MH_01_easy`、`V2_03_difficult`）
未被筛除。固定配置重复运行 `V1_01`、`V1_03`、`V2_03` 均成功，但 `V1_03`
ATE 漂移约 8.35%，说明困难序列受启动首帧/特征跟踪路径影响，后续应报告多次
重复统计。针对这一困难序列又固定 `delta_beta=4.0` 扫描了 `delta_alpha=2/4/8`，
ATE 为 `0.199085/0.197663/0.182272 m`，三次均成功；结果单独保存，未覆盖正式
`alpha=4.0` 汇总。当前剩余阻塞不是接口，而是作者修改后的单通道增强 checkpoint
与训练细节不公开。后续结果必须继续标记为 clean-room proxy，获得作者权重后另建
官方对照列。
